# Part A｜定位重构说明

## A1. 为什么要改定位：三个表层理由，三个深层病症

| 表层理由 | 深层病症 | 本次改动如何回应 |
|---|---|---|
| 飞检已做几轮，医院有经验，十几二十万心痛 | **成本中心叙事**——院长不为「概率性罚款」付确定性支出（损失厌恶） | 价值主张改述为经营语言：绩效管得住、迎检成本降下来、结余做正 |
| 医保局有免费事前预判接口，为何还要买 | **预警单点被替代**——免费工具覆盖通用规则弹窗 | 主卖点从「事前预警」后撤为「检查组视角的模拟与证据链」，这是免费工具结构上做不了的 |
| 仅定位数据合规操作，显得小 | **格局被合规锁死**——院长归为「信息科/医保办的事」 | 品类名升维为运营治理与决策支持，直接对话决策层 |

## A2. 名称决策

| 候选 | 判断 | 理由 |
|---|---|---|
| 医院运营数据**监管**服务平台 | 不采用 | 「监管」缺主体——监管是上级对下级的动作，医院是被监管方；让医院买「监管自己的平台」自带压迫感，决策层抵触 |
| 医院运营数据**治理**服务平台 | 部分采用 | 中性、建设性、格局打开；但偏IT语境，院长仍归为信息科项目，需补价值层 |
| **医院运营数据治理与决策支持平台** | **采用** | 保留治理方向 + 加「决策支持」把话说到院长耳朵里；对内保留合规视角作为独门方法论 |

## A3. 三层定位结构（对外一个名，对内一套逻辑）

- **第一层·品类名（对外统一口径）**：医院运营数据治理与决策支持平台
- **第二层·价值主张（对院长说的话）**：让检查结果看得见、运营绩效管得住、迎检成本降下来
- **第三层·尖刀场景（打开缺口的入口）**：模拟飞行检查报告 → 数据质量体检 → 国考指标沙盘

**核心打法**：以「运营治理」立名，以「合规检查视角」为不可替代的尖刀能力。合规从「主卖点」退为「独家方法论」，但绝不放弃。

## A4. 必须警惕的反直觉风险

升维到「运营治理」等于主动进入红海——卫宁、东软、国新健康、创业慧康都在「运营」名下已有成熟产品，在它们的主场硬碰硬会丢失「中立第三方合规层」的稀缺位置。
**对冲方式**：叙事上升维、能力上守住检查视角、切入上从单点尖刀进——先卖「检查组视角模拟」建立信任，再长成全院运营治理底座，**不要一上来就自称大而全的运营平台**（那是巨头的打法，不是新进入者的打法）。

# 一、一句话定位

面向医院决策层的**运营数据治理与决策支持平台**：用一套可信的数据底座，把散落在 HIS/EMR/病案/医保结算/收费系统里的数据治理干净，再以「检查组视角」把风险、绩效、评级结果提前模拟出来——让院长在检查组上门、在季度绩效公布之前，就知道会看到什么、会丢多少分、该先改哪里。

不是迎检填表工具，不是 BI 报表，也不是又一个 HRP——**是院长的「运营风险与绩效驾驶舱」，而它的独家仪表盘，是检查方视角。**

> 与 v0.3 的差异：主语从「医院」变成「院长决策层」；动词从「合规」变成「治理+决策」；价值从「通过检查」变成「看得见、管得住、降成本」。

## 三大价值支柱（对决策层的完整表述）

| 支柱 | 对院长的话 | 底层能力 |
|---|---|---|
| 看得见 | 「检查组会看到什么，我提前看到」 | 检查组视角模拟、多源数据交叉核验、证据链归集 |
| 管得住 | 「数据质量、运营绩效、合规风险，一屏掌控」 | 数据质量体检、国考/运营指标看板、风险预警 |
| 降成本 | 「迎检少加班、少被罚、少做无用整改」 | 整改闭环、模拟自查替代多轮突击、规则库持续更新 |

## 成功指标（建议口径，待与客户共定）

| 指标 | 定义 | 目标值（建议，需验证） |
|---|---|---|
| 迎检准备工时下降率 | 模拟报告替代人工自查后节省的人天 ÷ 基线人天 | ≥50% |
| 数据质量达标率 | 五维度抽检达标条目 ÷ 抽检条目 | ≥80%（对应否决线） |
| 风险前置发现率 | 上线后自查发现并整改的问题数 ÷ （自查+检查发现问题数） | 逐季提升 |
| 国考指标可追溯率 | 关联到底层取数口径与佐证材料的指标数 ÷ 国考指标总数 | ≥90% |
| 模块加签率 / 年续约率 | 底座客户中加签模块比例 / 到期客户续约比例 | 加签≥40%、续约≥80% |

# 二、为什么是现在（时机判断）

| 政策变量 | 关键事实 | 对本产品的意义 | 确定性 |
|---|---|---|---|
| 四标合一 | 电子病历分级、智慧服务、互联互通、智慧管理合并为《数智医院建设与应用评价标准》；2026 年底旧体系收尾，**2027 年有望启用，标准仍在研制** | 所有医院需重新迎评，确定性窗口，但规则未定 | 中高 |
| 数据质量单项否决 | 数据有效应用率 <80% 对应条目直接零分，按唯一性、完整性、合规性、同一性、时效性五维度核查 | 数据质量从「加分项」变「生死线」，是运营治理的硬指标 | 高 |
| 评审模式变革 | 五级以上取消现场审核、改远程线上评审、全程留痕 | 证据链结构化归集成为刚需 | 高 |
| 飞检高压常态化 | 2026 上半年国家飞检覆盖全国，查处涉嫌违规金额 11.6 亿；自查自纠退回 72 亿、占追回总额 44% | 医院有强动机先自查；检查视角模拟的价值基础 | 高 |
| 医保智能监管规则开放 | 国家医保局已发布 19 批规则/知识点，《规则库、知识库（2025 版）》出版发行；事前提醒系统接入率已达 71% | 通用预警被免费覆盖 → 必须转向「检查视角模拟 + 经营决策」 | 高（构成威胁） |
| 支付资格「驾照式记分」 | 监管到人，2026 上半年记分 5.4 万人次，暂停 324 人、终止 166 人 | 管理者与医生个人都有合规压力——被低估的个人侧切口 | 高 |
| 医保 3.0 / DRG-DIP 3.0 | 按病种付费分组 3.0 版计划 2027 年执行；行业向「数据运营服务」转型 | 院长真正的焦虑从「检查」扩展到「结余与运营」，正是「决策支持」的政策土壤 | 中高 |

**核心洞察（重构版）**：四套检查分属医保局、卫健委，口径各异，但底层收敛到同一件事——**数据的真实性与合规性**；而院长真正愿意付费的，是把这件事翻译成**结余、绩效、排名、成本**的经营结果。「一次治理、多口径复用、经营侧呈现」——这是单一赛道厂商（只做医保合规、只做评级咨询、只做 BI）都做不到的位置。

# 三、目标客户：公立与民营，同一套底座，两种打法

**结论：所有医院都需要，但付费动机、支付能力和产品形态不同。**

### 公立医院（三甲/二甲）
- **动机排序**：国考排名 > 等级评审/数智评级 > 运营绩效与结余 > 医保飞检罚款
- **决策链**：院领导（绩效办/评审办牵头）→ 信息科 → 财务/医保办/病案室
- **痛点**：多套检查多头迎检、重复准备；数据散在 HIS/EMR/病案/医保结算等系统，口径打架；数据质量差但没人常态管；DRG/DIP 下结余压力上升
- **打法**：项目制切入（数据质量体检 + 模拟检查报告），逐步长成全院运营治理底座；客单价高、周期长、标杆效应强
- **标杆价值**：拿下 1–2 家头部三甲，全省复制

### 民营/社会办医
- **动机排序**：医保定点资格和飞检罚款是**生死问题**（驾照式记分、暂停/终止支付资格直接威胁生存）> 自查自纠避免处罚 > 评级（多为加分而非必须）
- **决策链**：院长/老板一人拍板，决策快
- **痛点**：几乎没有专职信息科和病案团队，是被飞检打击的重灾区；自查能力几乎为零；IT 预算同样有限
- **打法**：轻量 SaaS/订阅制，云化部署（脱敏规则引擎 + 本地只读同步库/数据探针，视院内条件选择，见 9.1/9.2），低门槛自助式「合规体检」；按床位/按模块/按检出效果分层定价，首单门槛压到 1–5 万级；**注意同步库需院内存储资源，报价时须明确由谁承担**
- **注意**：产品必须做到「接上数据就能出报告」，不能要求驻场三个月

**产品形态**：单一版本，按商务合同模块化授权——治理底座必选，决策支持模块按需授权，签约即开通、到期即停用。同一套代码和服务体系，靠授权清单适配不同预算和动机。

**被低估的切口**：驾照式记分「监管到人」意味着医生个人也有压力。面向科室/医生的「个人合规画像 + 责任留痕 + 申辩证据包」可能是比机构侧更容易付费的差异化产品，建议单独立项验证。

# 四、产品模块清单与授权划分（重排）

**叙事原则**：底座讲「治理」，模块讲「决策」，尖刀讲「检查视角」。对外不再以「应对飞检/应对国考」命名模块（那是防守型、职能级语言），改为经营语言；括号内保留原能力对应关系，便于内部对照。

## 4.1 治理底座（必选，随产品交付）

1. **运营数据接入与治理引擎**
   - 多源接入：HIS / EMR / 病案 / 医保结算清单 / 收费医嘱 / LIS-PACS
   - 术语与编码归一化：ICD-10 / ICD-9-CM3 / 医保目录映射
   - 数据质量体检：对标五维度（唯一性、完整性、合规性、同一性、时效性），输出「数据质量分」+ 80% 否决线预警
2. **统一口径与同一性核验中枢**（核心壁垒）
   - 病案首页 vs 医保结算清单 vs EMR vs 医嘱/收费的交叉核验——「同一性」的重灾区
   - 政策条文 → 可执行规则（SQL/逻辑规则/大模型语义规则）的「翻译」层
   - 指标口径变更留痕，保证可追溯

## 4.2 决策支持模块（按商务合同开通）

| 授权模块 | 包含功能（对外表述） | 内部对应原模块 | 目标客户动机 | 就绪度 |
|---|---|---|---|---|
| **检查风险决策** | 检查组视角模拟自查报告；风险点定位与整改建议；事前提醒补充（院内多源维度） | 应对飞检 | 公立、民营通用；民营生死需求 | 可立即售卖 |
| **运营绩效决策** | 国考指标沙盘与口径追溯（CMI、四级手术占比）；指标与佐证关联；DRG/DIP 结余与成本效率分析（**部分待建，见第十一章**） | 应对国考 + 新增经营分析 | 三级公立医院刚需、院长直接关心 | 部分可售卖 |
| **数智评级决策** | 评级条目自评与达标率预警；迎检工作台（证据归集、远程评审留痕）；一票否决项专项监控 | 应对数智医院/等级评审 | 有评级计划的医院 | 预授权+规则发布后激活 |
| **整改闭环** | 问题→派单→整改→复核→归档 PDCA，与各模块共用 | 整改闭环 | 所有客户，建议随模块捆绑 | 可立即售卖 |

> **模块口径说明（审核补充）**：本表是「按商务授权划分」，4.5 是「按建设分期划分」，两者是同一组能力的不同切法，不是两套模块。对应关系：**运营绩效决策**在 4.5 中拆为「国考指标沙盘」（一期）与「DRG/DIP 结余分析」（二期上）；**数智评级决策**对应 4.5「数智评级规则库」（二期下）。表中「可立即售卖」均以 9.3 接口尽调通过、按「能拿到什么就交付什么」为前提。

## 4.3 尖刀能力：检查组视角模拟引擎（不可替代项）

这是全产品的差异化核心，**不单独售卖，内嵌于各模块**：
- 以检查方口径组织数据，而非以院内报表口径——「模拟检查组会看到什么」
- 生成《模拟飞行检查报告》《模拟国考报告》《模拟评审报告》
- 输出证据链与整改优先级，直连整改闭环

> 这是医保局免费事前提醒工具结构上做不到的：免费工具给的是「规则弹窗」，这里给的是「检查方视角的完整判断与证据组织」。

## 4.4 AI 增强（高级授权包）

- 大模型语义质控：病历内涵与诊断/编码一致性比对——**辅助提示 + 人工复核**，不作为独立预警依据
- 政策条文自动规则化：新文件发布后辅助生成规则草稿，人工审核入库
- 运营问答助手：管理者直接问「这个科室的 CMI 为什么掉了」「这种情况会不会触发医保预警」

> **授权控制**：模块开关走 License 授权中心（离线授权文件 + 在线校验双模式，适应内网隔离）；规则库按模块分包更新，未授权模块不下发对应规则包。

> **产品形态边界**：一期交付「院内只读同步库 + 旁路报告」——只读订阅生产数据变更、不直连生产库、不写回生产（详见第九章）；二期在厂商配合下做医生工作站嵌入。合同须写明分期边界与同步库资源分担。

## 4.5 分期功能全景图与二期路线（本次新增）

**全部功能按四期铺开，一张表看清做什么、什么条件、什么时候做。** 每一期都有明确战略角色——一期打进门、二期留住院长、三期开新战场。

| 分期 | 战略角色 | 模块 | 核心功能 | 依赖/触发条件 | 授权方式 |
|---|---|---|---|---|---|
| **一期·现已可售** | 打进门（检查视角） | 治理底座（必选） | 多源接入与术语归一化；数据质量体检（五维度）；统一口径与同一性核验中枢 | 无（随产品交付） | 必选，随底座 |
| 一期·现已可售 | 打进门 | 检查风险决策 | 模拟飞行检查报告；医保事前预警补充；风险定位与整改建议 | 无 | 按模块授权 |
| 一期·现已可售 | 打进门 | 国考指标沙盘 | 指标看板与口径追溯；偏离预警；佐证包导出 | 无 | 按模块授权 |
| 一期·现已可售 | 打进门 | 整改闭环 | 问题→派单→整改→复核→归档 PDCA | 无 | 跨模块共用，建议捆绑 |
| **二期上·能力补齐** | 留住院长（经营分析） | DRG/DIP 结余分析 | 科室/病种/医生三维结余；亏损病例下钻；异常病例监测 | **阻塞级**：依赖院内 DRG/DIP 分组系统结果 + 成本数据 | 按模块授权 |
| 二期上·能力补齐 | 留住院长 | 科室经营画像 | 科室对比矩阵（CMI/RW/结余率/平均住院日/四级手术占比）；学科能力雷达；异常科室预警 | 依赖结余分析产出 | 按模块授权 |
| 二期上·能力补齐 | 留住院长 | 院长驾驶舱 | 国考预估排名/运营结余/合规风险一屏总览；「今日最该关注的三件事」；问答式查询 | 整合层，依赖前两者数据，最后建设 | 随模块交付 |
| **二期下·条件触发** | 等风来（政策与技术） | AI 增强包 | 大模型语义质控；政策条文自动规则化；运营问答助手 | 无外部政策依赖，技术随时可做；误报率须设阈值 | 高级授权包 |
| 二期下·条件触发 | 等风来 | 数智评级规则库 | 条目自评与达标率预警；迎检工作台；一票否决项专项监控 | **条件触发**：《数智医院建设与应用评价标准》正式发布后激活（2027 有望，现仍在研制） | 预授权+发布后激活 |
| **三期·新增长** | 开新战场（个人与事中） | 医生个人合规画像 | 个人合规画像；责任留痕；申辩证据包 | 先验证付费意愿；只作提示留痕，不作自动处分依据 | 待立项 |
| 三期·新增长 | 开新战场 | 医生工作站嵌入 | 医生端事前提醒弹窗（从事后报告升级为事中拦截） | **强依赖**：HIS/EMR 厂商配合，与「中立」定位有张力 | 待生态成熟 |

> **贯穿能力（不单独售卖）**：检查组视角模拟引擎——以检查方口径组织数据，生成模拟检查/国考/评审报告，内嵌于各期模块。这是免费工具结构上做不到的部分。

### 4.5.1 二期三类建设动机

| 类别 | 含义 | 包含模块 | 处理原则 |
|---|---|---|---|
| 能力补齐 | 一期承诺过、必须做完的「债」 | 结余分析、科室画像、院长驾驶舱 | 一条链：结余分析是地基，地基建不起来后两者是空壳，不可拆开单独承诺 |
| 条件触发 | 牌已备好、等外部条件成熟的「牌」 | 数智评级规则库（等政策）、AI 增强包（等技术） | AI 增强包不受政策卡脖子，可先做；数智评级只做预授权 |
| 新增长曲线 | 探索性、先验证再投入的新赛道 | 医生个人合规画像、医生工作站嵌入 | 小范围验证付费意愿与合规边界后再立项 |

### 4.5.2 售卖红线（写进销售规范）

1. 一期签约只承诺四项已就绪能力（治理底座 + 检查风险决策 + 国考沙盘 + 整改闭环）；
2. 结余分析合同须写明「依赖院内 DRG/DIP 系统就绪」的条件条款，未就绪不承诺交付；
3. 数智评级只做「预授权 + 规则发布后激活」，不收全款、不承诺达标；
4. 医生个人画像与工作站嵌入不进一期合同；
5. 签约前须完成 HIS/EMR/HRP 接口与同步授权可得性尽调（见 9.3），按「能拿到什么就交付什么」写进合同；EMR 全文与 HRP 成本数据不得写入一期硬承诺。

**分期逻辑线**：一期靠「检查视角」打进门 → 二期用「经营分析」把院长留下 → 三期用「个人 + 事中」开新战场。

# 六、商业模式：单版本 + 模块授权

| 收费项 | 说明 | 参考定价 |
|---|---|---|
| 治理底座（必选） | 数据接入治理引擎 + 统一口径/同一性核验中枢，含实施对接 | 实施费 15–40 万（视院内系统对接复杂度） |
| 决策支持模块 | 检查风险 / 运营绩效 / 数智评级，按模块加签 | 单模块 10–25 万/年；三模块打包 35–50 万/年 |
| 年度规则库订阅 | 政策强依赖，规则须年年更新，按已授权模块分包下发 | 含在模块年费中，续约即持续收入 |
| AI 增强包 | 大模型语义质控、运营问答等高级功能 | 加签 5–15 万/年 |

**分层定价（民营）**：按床位/模块/检出效果分层，首单 1–5 万级；把「生死需求」转化为「低客单、高频、快复制」。三甲维持项目制定价。

**关键设计**：
- 底座 + 模块降低首次签约门槛——先买最痛的一个模块，用出价值后逐年加签；
- 规则库订阅绑定模块，形成天然续约动力——政策年年变，停约即规则停更；
- 公立走项目制入预算，民营走轻部署纯订阅，产品同一套，实施与服务深度不同。

**单位经济模型（待财务填充）**：LTV/CAC 模型，重点跟踪模块加签率、年续约率、实施人天。**这三个数跑通前不宜扩大销售团队。**

# 七、竞争与差异化（重写）

## 7.1 竞争格局：升维后进入红海，必须靠尖刀区隔

| 玩家类型 | 代表厂商 | 已占位置 | 与本产品的关系 |
|---|---|---|---|
| 院内核心系统厂商 | 卫宁健康（8000+医院）、东软、创业慧康 | HIS/EMR/病案/DRG 分组器一体化，事前提醒已内嵌 | 既是合作方也是最大竞争对手；接口开放与否决定生死 |
| 医保+医院双端运营服务 | **国新健康** | DRG/DIP/APG 全套、病案质控、拒付风控托管、按年收运营费 | 商业模式几乎完全重合，最直接对手；也是「运营」叙事下的强敌 |
| 医保局侧平台建设者 | 金仕达卫宁、创业慧康、久远银海、太极股份 | 承建国家/省级医保智能监管平台、两库运维 | 掌握规则源头，可能向下游延伸 |
| 高端病案/付费管理 | 嘉和美康 | 三甲高端病案与付费管理系统 | 直接争夺同一批三甲客户 |
| AI 编码/数据增值 | 万达信息、麦迪科技、麦博、汇美云等 | AI 病案编码、入组校验、成本复盘 | 在 AI 语义质控维度正面竞争 |
| 通用 BI/运营平台 | 各类 BI、HRP、绩效核算厂商 | 运营看板、成本核算 | 「决策支持」叙事下的泛竞争者（能力弱但数量多） |

行业格局：DRG/DIP 系统 CR5 约 65%，已进入头部集中阶段；SaaS 化在中小医院接受度提升（2026 年云端占比约 35%）。

## 7.2 差异化：只押三件事（重构版）

1. **检查方视角模拟**——「我模拟检查组怎么查你」。这是院内系统厂商不会做、医保平台不愿做、BI 厂商做不了的中间位置。**这是升维后唯一不能丢的锚点。**
2. **多口径证据链复用**——同一份数据治理成果，自动生成检查自查报告、国考指标佐证、评审条目证据包。单点厂商做不了，这是「统一底座」唯一站得住的价值。
3. **中立 + 不触碰生产接入**——不卖 HIS、不替换核心系统，以院内只读同步库订阅变更数据、不直连不写回（见 9.2）；对厂商是增量而非威胁，才有合作可能。**注意**：同步库方案比「探针」交付更重（需在院内落存储），「轻量」仅指对厂商生产系统的侵入性低，不等于实施成本低，报价与话术不可混用。

**必须放弃的幻想**：不要宣称「政策翻译能力是壁垒」——头部厂商的医保专家团队规模远超初创公司；不要宣称「大而全的运营平台」——那是巨头主场。
**真正的壁垒**：结构化规则库 + 跨客户数据基准（benchmark）+ 检查视角方法论 + 整改闭环形成的历史数据切换成本。

# 八、GTM 落地路径（重写话术）

## 8.1 公立：标杆先行，自上而下
1. **选点**：1–2 家关系最强的三甲，免费做「数据质量体检 + 模拟检查报告」，换真实规则反馈与案例授权；
2. **切入**：从院领导/绩效办/评审办入手（有考核压力），而非信息科（只关心别添乱）；
3. **话术**：不说「买合规工具」，说「让院长提前看到检查结果、把迎检成本降下来」；
4. **转化**：体检报告 → 治理底座实施费 → 第一个决策模块 → 逐年加签；
5. **复制**：以标杆医院名义办区域研讨会，省内批量复制；
6. **销售周期**：预计 6–12 个月，按项目制配置售前与实施资源。

## 8.2 民营：产品自助，渠道放量
1. **产品**：接上数据就能出报告，全程自助，无驻场；
2. **渠道**：行业协会、医管集团、连锁医疗集团批量签约；
3. **定价**：低门槛订阅（1–5 万级），按床位/模块分层；
4. **触达**：以《模拟飞检报告》作为免费引流物料，制造「不看不知道」的焦虑；
5. **算账**：把「被飞检罚一次够买十年产品」用真实案例说清。

## 8.3 生态位策略
主动对接卫宁、东软、创业慧康等厂商，争取成为其「合规增强层/检查视角插件」的合作伙伴。厂商渠道可能比自建销售更快放量——升维到「运营」后更要把自己放在「补充者」而非「替代者」位置。

# 九、技术架构与部署

```
[院内生产域] HIS / EMR / 病案 / 医保结算 / 收费医嘱 / LIS PACS（厂商运维，不直连）
        │  CDC 增量订阅 + 字段白名单 + 脱敏（秒~分钟级延迟）
        ▼
[院内同步库] 最小必要字段集 · 只读副本 · 我方运维 · 与生产性能隔离
        │  大量读取（读操作全部落这里）
        ▼
[接入与治理层] 多源适配 + 脱敏 + 术语/编码归一化（ICD-10 / ICD-9-CM3 / 医保目录）
        ▼
[治理底座] 数据质量引擎（五维度） + 同一性核验中枢（多源交叉比对）
        ▼
[规则与视角层] SQL规则 / 逻辑规则 / 大模型语义规则 + 检查方视角模拟引擎
        ▼
[决策模块] 检查风险 | 运营绩效 | 数智评级 | 整改闭环 —— License 开关控制
        ▼
[输出层] 模拟检查报告 / 指标看板 / 证据包 / 整改工单 / 管理者问答 / 医生端提示（二期）

[写路径] 一期：整改工单 / 标注 / 规则配置 / 报告状态 → 全部写我方自有库，零写回生产
         三期：医生工作站提醒 → 走厂商标准接口写回，量极小
```

## 9.1 三类系统接口策略与就绪度

| 系统 | 接入方式 | 最小必要同步内容 | 主要卡点 | 一期策略 | 就绪度 |
|---|---|---|---|---|---|
| **HIS** | CDC 订阅 / 只读视图 / 定期导出 | 入出院记录、医嘱、收费明细、患者主索引 | 厂商库权限、表结构不开放；字段相对标准 | 必接。分解住院 / 低标准入院 / 重复收费等规则即可跑出模拟报告 | 高 |
| **EMR** | 优先 ODR / 病案系统旁路；全文再谈 CDC 或接口 | 病案首页、出院诊断、手术操作、文书标题与关键段落（非全文） | **最难**：库大、全文非结构化、权限最紧 | 一期只接结构化字段；语义质控列为二期增强，合同写「视接口开放程度交付」 | 低（阻塞尖刀完整度） |
| **HRP** | 定期导出 / 接口，不同步全库 | 科室级成本、病种级成本（可得则取） | 财务科不愿放数据；厂商按次收费 | 二期再谈，签约前做成本可得性尽调；到不了病种级就降级为科室级粗算 | 低（阻塞结余分析） |

> **关键矛盾**：一期喊「不动业务系统」，但尖刀能力（语义质控、多源同一性核验）依赖 EMR 全文——EMR 恰是三类里最难接的。若 EMR 拿不到，差异化论证会打折。因此一期只承诺不依赖 EMR 全文的规则，把全文质控作为条件激活项。

## 9.2 同步库方案：读写分离（本次新增）

**核心原则：读全走同步库，写尽量不回生产。** 这比单纯「读写分离」更彻底，厂商阻力最小。

1. **不做全库镜像，只同步字段白名单。** HIS/EMR 生产库常达 TB 级、上千张表，全量同步既撑不住存储，也更过不了厂商审批。只同步 9.1 表列的内容，同步库通常可压到几十 GB 量级——这是厂商愿意点头的前提。
2. **脱敏前置到同步管道。** 姓名、身份证、电话在同步层哈希化，落到同步库的已是脱敏数据；全程审计「谁在何时读了什么」。
3. **延迟有明确边界。** CDC 同步是秒级到分钟级：对事后报告、治理核验、迎检模拟、国考分析完全够用；**但撑不了「事中拦截」**——三期医生工作站提醒必须走厂商实时接口，不能靠同步库。
4. **写路径极窄。** 一期平台产生的写操作全落我方自有库；唯一写回生产的是三期提醒消息，且写的是提醒而非病历。

**必须承认的四项代价**（写进报价与实施边界）：
- **交付变重**：从「只读探针轻交付」变成「院内落一套存储」，需向院方争取服务器/存储资源，报价中应体现；
- **链路运维**：同步中断要有断点续传与对账校验，否则报告基于旧数据会直接砸口碑；
- **权限谈判没消失**：厂商仍需授权 binlog/OGG 订阅或复制权限，只是从「让我们读生产」变成「让我们订阅变更」，阻力降低但不为零；
- **数据不出院**：同步库含 PHI，必须院内部署，同受脱敏/审计/加密/等保约束，不能上公有云。

**政策借力**：互联互通测评、数智医院评级均要求数据互通，OFD-H 国标 2027-04 实施——把「协助院方推动厂商开放标准接口与订阅权限」做成售前服务项，比硬啃技术更现实。

## 9.3 接口就绪度售前检查清单（签约前逐项确认）

- [ ] HIS 能否提供只读订阅或视图？覆盖哪些表、字段？
- [ ] EMR 结构化字段（首页 / 出院诊断 / 手术操作）能否从 ODR 或病案系统旁路取得？
- [ ] EMR 全文能否拿到？若不能，二期语义质控是否接受降级为「结构化字段质控」？
- [ ] HRP 成本数据能否到病种级？财务科是否签字？接口是否另收费？
- [ ] 院内能否提供同步库服务器/存储资源？由谁承担？
- [ ] 厂商是否书面同意订阅/复制授权？
- [ ] 脱敏规则与审计要求是否经院方信息科确认？

**部署模式**：
- 公立版：数据不出院，院内私有化部署（含同步库），最小权限、全程审计、国密、信创适配；
- 民营版：本地同步库（最小字段集）+ 云端规则引擎，原始数据不出院，仅上传脱敏结果与特征；
- 授权中心：离线授权文件 + 在线校验双模式，适应内网隔离；
- 规则包：按模块分包更新，未授权不下发。

# 十一、能力缺口与补齐路径（本次新增，必读）

**定位升维的最大风险是「新瓶装旧酒」被识破。** 当前能力重心在合规与数据治理，「运营绩效决策」若只有国考看板而无真正的经营分析，会被院长当场戳穿。必须诚实规划：

| 定位承诺 | 当前能力 | 缺口 | 补齐路径 | 未补齐前的对外话术 |
|---|---|---|---|---|
| 检查结果看得见 | 强：规则库+模拟报告 | 规则覆盖度依赖持续运营 | 按省飞检清单扩充 | 可完整承诺 |
| 运营绩效管得住 | 中：国考指标看板 | 缺 DRG/DIP 结余分析、成本归集、科室经营画像 | 与成熟 DRG/DIP 厂商合作或自研，列为二期上；**阻塞依赖：院内 DRG/DIP 分组系统结果 + 成本数据，未就绪则整条链（结余分析→科室画像→驾驶舱）无法交付** | 先讲「指标口径可追溯」，不承诺「结余优化」，避免与 HRP 正面对标 |
| 迎检成本降下来 | 中：模拟自查+整改闭环 | 缺工时下降的实证数据 | 试点期采集工时基线做对照 | 用试点数据说话，不空口承诺百分比 |
| 尖刀·检查视角完整度（审核补充） | 强：规则库+模拟报告 | **EMR 全文接口为阻塞级依赖**（见 9.1/9.3）；拿不到则低码高编语义质控、三源同一性核验降级，差异化论证打折 | 签约前尽调；拿不到全文则一期只承诺不依赖全文的规则，全文质控列条件激活 | 一期只讲「结构化字段可拿到的检查视角」，不承诺全文语义质控 |
| 交付形态（审核补充） | 原「只读探针轻交付」 | 同步库方案需院内存储 + 链路运维，交付变重（见 9.2） | 报价中单列存储资源与运维成本；政策借力推动厂商开放订阅权限 | 不说「零部署」，说「不动生产库、不写回生产」 |

**原则**：先以「检查视角 + 指标可追溯」立住脚，再把经营分析作为模块逐步放出。**宁可少承诺，不可被识破。**

# 十二、里程碑与验证指标

| 阶段 | 目标 | 验证指标（Go/No-Go） |
|---|---|---|
| M0 定位验证（新增） | 用新叙事测试决策层付费意愿 | 3–5 家目标医院院长/运营副院长听完后明确表示「这是院级项目」且愿谈预算 |
| M1 产品验证 | 脱敏数据跑出《模拟检查报告》样例 | 报告被目标医院认可为「有价值的自查视角」；规则可解释、可复核 |
| M2 付费验证 | 1–2 家标杆签约底座 + 首模块 | 首单成交；实施人天在预算内；加签意愿明确 |
| M3 模式验证 | 民营版自助化 + 渠道试点 | 首单门槛达成；自助完成率 > 60%；续约意向明确 |
| M4 规模化 | 省内复制 + 厂商生态合作 | 年续约率 > 80%；模块加签率 > 40%；实施人天逐季下降 |

**PMF 判定**：续约率与加签率同时达标，才说明模式跑通；否则回到 Part A 重新校准定位。

# 十三、风险与红线

1. **不承诺「保证通过」任何检查**——始终是辅助自查与风险预警，话术红线写进销售规范；价值锚点放在过程指标（数据质量分、达标率、预警数、整改闭环率、证据链可追溯）。（对应成本中心叙事风险）
2. **自身合规必须滴水不漏**——卖合规的公司自己出数据安全事故就是致命打击：最小权限、全程审计、国密、信创适配、数据不出院。涉及患者个人信息一律脱敏处理。
3. **政策依赖**——标准每年变，须专职规则运营团队；数智模块按「预授权+规则发布后激活」规避空头承诺。
4. **实施风险**——公立接口协调是时间黑洞；一期走院内只读同步库（订阅授权谈判 + 院内存储资源 + 链路运维，见 9.2），签约前完成 9.3 尽调；二期再谈工作站嵌入，合同写明边界。
5. **免费公共产品替代风险**——医保局事前提醒免费且接入率 71%；价值必须落在官方不覆盖的维度（检查视角模拟、多源同一性、证据链、经营决策）。
6. **红海竞争风险（升维新增）**——「运营治理」是巨头主场；以检查视角为锚点，不与 HRP/BI 正面对标，能力缺口未补齐前不夸大经营分析承诺。
7. **个人合规切口**——面向医生个人的合规画像须注意劳动与人事合规边界，仅作提示与留痕，不作自动处分依据。

# 十四、下一步（建议顺序）

1. **先做 M0 定位验证**：拿新话术（运营治理 + 检查视角）见 3–5 位院长/运营副院长，确认「院级项目」认知与预算意愿——**这一步不过，后面都不要做**；
2. **做尖刀 Demo**：脱敏病案首页 + 费用数据跑出《模拟飞行检查报告》样例，作为最好的销售物料；
3. **选点试点**：1–2 家关系最强的医院免费体检，换案例与真实规则反馈，同时采集迎检工时基线；
4. **补能力缺口**：启动 DRG/DIP 结余与成本分析的可行性评估（合作或自研）；
5. **建规则同步渠道**：跟医保局/病案质控中心建立规则同步渠道；
6. **验证个人合规切口**：小范围测试医生个人「合规画像 + 责任留痕」概念；
7. **民营放量**：自助化产品成熟后，走行业协会/医管集团渠道放量。
